# V2 升级规划：Windows 本地 PDF 脱敏水印权限工具

版本：V2 草案  
日期：2026-06-07

## 1. V2 目标

V1 解决“能安全处理单个 PDF”。  
V2 解决“更自动、更批量、更适合真实办公流程”。

## 2. 候选升级方向

### 2.1 OCR 自动脱敏

目标：

- 支持扫描件自动识别敏感文字。
- 支持图片中的手机号、身份证号、邮箱。

可选底座：

- Umi-OCR，本地化较好，中文体验好。
- PaddleOCR，识别能力强，但依赖更重。
- Tesseract，轻量，但中文体验需要调参。

建议：

- V2 优先接 Umi-OCR 或 PaddleOCR。
- OCR 模块做成插件式，不污染 V1 核心。

### 2.2 批量处理

功能：

- 文件夹批处理。
- 多 PDF 队列。
- 批量添加同一水印。
- 批量权限密码。
- 每个文件单独报告。

风险：

- 自动脱敏漏检风险更高。
- 需要“处理前抽样预览”和“处理后风险报告”。

### 2.3 高级手动编辑

功能：

- 框选区域可拖拽调整。
- 多选框。
- 复制上一页脱敏框到下一页。
- 对整页固定区域批量脱敏。
- 快捷键。

### 2.4 图片水印和动态水印

功能：

- 图片水印。
- 页脚水印。
- 每页显示处理时间、文件名、操作人。
- 动态追踪码。

### 2.5 脱敏模板

功能：

- 保存规则模板。
- 合同模板脱敏框。
- 报表模板脱敏框。
- 按页码范围应用。

### 2.6 更强验证

功能：

- 对输出 PDF 做 OCR 复检。
- 对图片型 PDF 检查可疑数字串。
- 生成 HTML/PDF 验证报告。
- 支持敏感内容风险等级。

### 2.7 审计与合规

功能：

- 操作日志签名。
- 处理报告不可篡改 hash。
- 文件 hash 记录。
- 操作人字段。
- 本地审计导出。

## 3. V2 技术路线建议

保留 V1 核心：

- PyMuPDF 仍做 PDF 核心。
- pikepdf/qpdf 仍做权限和结构。
- Tkinter 可继续用。

新增模块：

| 模块 | 建议 |
|---|---|
| OCR | 插件式 `ocr/provider.py` |
| 批量任务 | `queue` + worker thread |
| 模板 | JSON 配置 |
| 报告 | HTML + JSON |
| 验证 | 文本验证 + OCR 验证 |

如果 V2 UI 复杂度明显增加，可以评估：

- PySide6：更强桌面 UI，但依赖更重。
- 本地 Web UI：FastAPI + 浏览器，但打包和本地服务管理更复杂。

V2 早期仍建议保留 Tkinter，先把业务能力补齐。

## 4. V2 里程碑

### V2.1 OCR 插件

- 接入 OCR。
- 扫描件自动候选框。
- OCR 结果人工确认。

### V2.2 批量处理

- 文件队列。
- 批量规则。
- 批量水印。
- 批量报告。

### V2.3 模板化

- 保存模板。
- 套用模板。
- 页码范围。

### V2.4 审计报告

- 操作人。
- 文件 hash。
- 敏感类型统计。
- 验证结果。

## 5. 不建议过早做的事

- 不建议 V2 就做账号权限系统。
- 不建议做云端同步。
- 不建议做复杂 DRM。
- 不建议做 PDF 编辑器级别的全部能力。
- 不建议一开始重写成大型 Web 平台。

## 6. V2 最佳升级顺序

1. OCR 自动候选。
2. 批量处理。
3. 模板。
4. 审计报告。
5. 更复杂 UI。

原因：OCR 和批量处理最直接提升实际效率；模板和审计再提高长期使用价值。
